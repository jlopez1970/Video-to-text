**Version:** 1.5 (2026-09-11) — largest single validation pass yet (372 cue-text edits on one file), which surfaced the most severe confirmed instance so far of the "dado" false-negative problem (dozens of missed Dow references in one document, not caught even though "dado" used as Dow was fixed cleanly in other passes), plus several new high-frequency ticker variants that were never touched at all: "Nasda" (23×), "daoyon"/"daoyón" (24×, a fused "Dow Jones" spelling), "nasta" (9×), "piwa" (4×, SPY), "IVAP" (3×, VBAP), "dado y once" and "nazar" (1× each). See the Validation log entry below for full detail. Version 1.4 (2026-08-28) read the production script (`transcript_corrector.py`, part of a local "video-to-text" app that downloads/transcribes/corrects) and fixed several bugs it had relative to this glossary: "dado" was a blind substitution (now contextual, see the Dow row), the "amad" context check only looked at the immediately adjacent word (now a wider window), a duplicate dict key silently dropped one of two "bebap" mappings (now pulled pending verification, see Unresolved), and a new context-dependent "ggl"→GOOGL-or-GGLL check was added (see the GOOGL row). Also added the entries the script was missing relative to this glossary at the time (Spi Guay, cols/coals, Dow Jon, COD/SOXL, déjenlo quieto, estopco). Versioning started at 1.0 (2026-08-22); the update history from 2026-08-21 (before versioning was introduced) is preserved below in the Validation log.

**Purpose:** Whisper-based transcription (tested at `tiny`, `medium`, and `large` model sizes) consistently mis-hears the same set of tickers, index names, and jargon in these recordings. This glossary documents the recurring errors so any LM correcting a new VTT/transcript from this same source can fix them via direct substitution instead of re-deriving them from scratch each time.

**Source:** Built from a three-way comparison of `20260817 M3 tiny.vtt.txt`, `20260817 M3.vtt.txt` (medium), and `20260817 M3 large.vtt` — an instructor-led live trading class, spoken in Spanish with English financial tickers/terms mixed in. Validated against real correction passes from multiple sessions by the same instructor (trading class "M3"/"M4"/"M5" and an "AI Fundamental" module) — the same tickers, indicators, and jargon recur across sessions, so this glossary applies across the instructor's catalog, not just the M3 recording.

**How to use this with an LM:**

- **Interactive (pasting into a chat):** paste the transcript segment plus this glossary and ask the model to replace every garbled form with its correct form *only when the surrounding context matches the described meaning* — several of these garbled strings are ambiguous out of context (see notes column).
- **Scripted / API pipeline:** load this file's full text and pass it as context alongside each transcript chunk in your correction call (e.g. embed it in the system/instructions parameter, or prepend it to the user message before the transcript) — don't rely on it as a static find-and-replace table. This glossary is *not* safe to apply as blind regex/string substitution: several entries are explicitly ambiguous (marked "Caution" — e.g. "dado"/"nada" are also ordinary Spanish words, and a naive substitution has produced confirmed wrong output — "se han dado cuenta" → "se han Dow cuenta" — in real runs; see the Dow row and the Validation log below), and a few require picking between two real tickers by context (e.g. "amad" → AMAT or AMD, "ggl" → GOOGL or GGLL depending on whether a leveraged-ETF context is present). If your script needs a substitution step that runs without an LLM in the loop (pure regex/string replace), only apply the rows that carry no "Caution"/context-dependency note in this document, and route anything ambiguous to a human or a model call instead. Re-fetch this file per run rather than caching a copy — it's actively updated (see the version line above and the Validation log's running history).

## Known transcription failure modes by model size (for reference)

- **tiny**: heavy fragmentation (many more, shorter cues than medium/large), occasional hallucinated foreign-script insertions during music/unclear audio, and degenerate repetition loops (a phrase or word repeated many times in a row).
- **medium**: consistent, patterned phonetic substitutions for tickers/proper nouns (see tables above) — the most predictable and easiest to correct via glossary.
- **large**: highest per-word accuracy and correct spelling of tickers/names, but prone to complete content dropout on quiet/musical/ambiguous audio, replacing minutes of real audio with a single repeated filler word (e.g. "Gracias." repeated across many consecutive cues) rather than an attempt at transcription. Also shows shorter repetition loops similar to tiny's.

## Known cross-transcript comparison failure modes (for reference)

Separate from single-transcript correction accuracy, comparing *two different raw transcripts of the same recording* (not a corrected-vs-raw pair) surfaces its own patterns, seen when diffing `20260810 M3.docx` against `20260810 M31.docx` (2026-08-28):

- Two independent transcription runs of the same audio can match **word-for-word, including timestamps, for an extended opening stretch** (196 consecutive cues / ~20.5 minutes in this case) and then diverge for the remainder — re-chunked differently, ~91% word-level similarity, mostly minor wording/punctuation drift plus recurring ticker/jargon mis-hearings unique to each run.
- Two transcripts of the same class/module can also differ by one being a **strict subset** of the other — i.e. one file is missing whole contiguous stretches of verbatim-identical captions (seen when diffing `20260810 M4.docx` vs `20260810 M41.docx`: M4 was missing 44 captions across 4 gaps that M41 had, all other captions byte-identical, gaps skipped in numbering rather than renumbered). Worth checking for this pattern (identical text, but one file simply shorter) before assuming a divergence is due to re-transcription.
- Two uploads can also simply be **duplicate files** (seen with `20260810 M5.docx` vs `20260810 M51.docx` — identical MD5 checksum). Worth an MD5/size check first before doing any content diff, to short-circuit accidental duplicate uploads.
